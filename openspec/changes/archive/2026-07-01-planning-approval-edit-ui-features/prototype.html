화면 흐름
  1. skeleton 단계 진입 → 프로젝트의 features 제안 큐를 fetch.
  2. 제안 ≥1건 → 노드별 [현재 속성 → 제안 속성] 대비 카드(nodePath 경로 표시) + 개별 [승인]/[반려] + 하단 [모두 승인]/[모두 반려].
  3. 개별 승인 → 그 노드의 features.md 헤더 직후 속성 줄만 교체(산문·capability·위계 보존), 큐에서 제거. 반려 → 반영 없이 큐에서 제거(원본 불변).
  4. 제출 후 features 트리·큐 재조회(dashReqToken race 가드). 큐가 비면 → 순수 읽기 트리 뷰(승인 UI 숨김).
  5. 미실재 id/nodePath는 skipped로 표면화(silent drop 금지). self-roundtrip 불변식(노드 개수·capability 불변) 위반 시 422로 원본 보호.
