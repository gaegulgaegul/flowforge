## spec.md 숨은 빌드산출물화
<!-- capability: spec-md-build-artifact -->
(중요도: 높음, 상태: 시작전)

docs/spec.md를 사람이 편집하는 문서에서 features.md로부터 재생성되는 **빌드 산출물**로 강등한다(안2). 사람은 features/user-flow만 편집하고 spec.md는 손대지 않는다 — spec.md는 audit이 코드와 대조하는 기계용 검증 기준일 뿐이다. flowforge는 이미 spec.md를 문서 뷰로 띄우지 않으므로 사용자 편집 경로가 없다.

### AUTO-GENERATED 마커
(중요도: 높음, 상태: 시작전)

#### 재생성 산출물 헤더 주입
(중요도: 높음, 상태: 시작전)

spec.md 최상단에 "AUTO-GENERATED from features.md — do not edit by hand" 마커를 박아, 이 파일이 사람 편집 대상이 아니라 빌드 산출물임을 명시한다.

### 손편집 감지·재생성
(중요도: 높음, 상태: 시작전)

#### 손편집 감지
(중요도: 중간, 상태: 시작전)

spec.md가 마지막 재생성 이후 사람 손에 직접 수정됐는지 감지한다(예: 체크섬/타임스탬프 대조). 손편집이 감지되면 표면화하고, 다음 재생성이 손편집을 덮어씀을 경고한다(사람은 features.md를 고쳐야 함).

#### features.md → spec.md 재생성
(중요도: 높음, 상태: 시작전)

features.md 변경 시 spec.md를 audit 라인문법으로 재생성한다(openspec-plan의 spec.md 변환 절차를 재사용). 영문 capability 키는 불변으로 보존한다.

### audit 읽기전용 소비
(중요도: 중간, 상태: 시작전)

#### audit만 spec.md 참조
(중요도: 중간, 상태: 시작전)

spec.md의 유일한 소비자는 openspec-audit(코드 대조)이다. audit은 spec.md를 읽기만 하고 변경하지 않는다(readonly invariant). flowforge 뷰·사람 편집 경로는 spec.md를 건드리지 않는다.

## 화면 1급 노드 + N:M 연결
<!-- capability: screen-first-class-node -->
(중요도: 높음, 상태: 시작전)

manyfast식으로 화면(페이지)을 기획 명세의 **1급 엔티티**로 두고, 상세기능을 화면에 N:M으로 연결한다. 유저플로우·와이어프레임·IA 세 뷰가 같은 화면 노드를 공유해 뷰 간 정합성을 보장한다(한 화면 정의를 여러 뷰가 참조).

### 화면 1급 엔티티 정의
(중요도: 높음, 상태: 시작전)

#### 화면 노드 스키마
(중요도: 높음, 상태: 시작전)

화면(페이지)을 기획 명세에 독립 노드로 정의한다(요구사항·기능·상세기능과 나란한 1급 아이템). 각 화면은 안정적 식별자를 가진다.

### 상세기능 ↔ 화면 N:M 연결
(중요도: 높음, 상태: 시작전)

#### N:M 연결 표현
(중요도: 높음, 상태: 시작전)

한 상세기능이 여러 화면에 나타나고 한 화면이 여러 상세기능을 담는 다대다 관계를 명세에 표현한다(연결 테이블/참조 목록).

### 세 뷰 화면 노드 공유
(중요도: 높음, 상태: 시작전)

#### 유저플로우·와이어·IA 뷰 정합
(중요도: 중간, 상태: 시작전)

유저플로우·와이어프레임·IA(정보구조) 세 뷰가 같은 화면 노드를 참조하도록 하여, 한 곳에서 화면을 고치면 세 뷰에 일관되게 반영된다(뷰 drift 0).

## 유저플로우 에지케이스 자동 분기
<!-- capability: userflow-edgecase-branches -->
(중요도: 중간, 상태: 시작전)

spec의 invariant safe-4xx·에러 THEN 절에서 예외(에지케이스) 경로를 유저플로우 분기로 자동 생성한다. 사람이 happy path만 그려도 spec 근거가 있는 실패 경로가 유저플로우에 자동으로 채워진다.

### 1단계 결정론 분기
(중요도: 높음, 상태: 시작전)

#### spec 근거 기반 분기 생성
(중요도: 높음, 상태: 시작전)

spec의 safe-4xx invariant·에러 THEN 절만을 근거로, 지어내지 않고 결정론적으로 에지케이스 분기를 유저플로우에 생성한다(근거=spec 라인).

### 2단계 AI 추론 분기(옵션)
(중요도: 낮음, 상태: 시작전)

#### AI 추론 에지케이스 제안
(중요도: 낮음, 상태: 시작전)

spec에 명시되지 않은 잠재적 에지케이스를 AI가 추론해 분기로 제안한다(옵트인). 결정론 분기와 구분하며, 지어냄 위험이 있어 사람 승인을 전제로 한다.

### 시각 구분(실선/점선)
(중요도: 중간, 상태: 시작전)

#### happy 실선·에지 점선 렌더
(중요도: 중간, 상태: 시작전)

happy path는 실선, 자동 생성된 에지케이스 경로는 점선으로 시각 구분해, 정상 흐름과 예외 흐름을 한눈에 구별한다.

## 뷰-데이터 단일그래프(종착지)
<!-- capability: unified-item-graph -->
(중요도: 중간, 상태: 시작전)

기획 아이템 4종(요구사항·기능·상세기능·페이지)을 하나의 통합 그래프 데이터 모델로 합치는 것이 이 기획 시스템의 **종착지**다. 모든 뷰가 단일 그래프를 각기 다른 렌즈로 투영한다.

### 4종 아이템 통합 그래프
(중요도: 중간, 상태: 시작전)

#### 단일 그래프 데이터 모델
(중요도: 중간, 상태: 시작전)

요구사항·기능·상세기능·페이지를 노드로, 그 관계(포함·N:M 연결)를 엣지로 갖는 하나의 그래프로 통합한다. **이것이 종착지 성격의 목표다** — 지금 당장이 아니라 결정2(화면 1급화)를 반복해 도달할 최종 형태.

### 증분 도달(빅뱅 금지)
(중요도: 높음, 상태: 시작전)

#### 화면 1급화 반복으로 접근
(중요도: 높음, 상태: 시작전)

전면 재작성(빅뱅)을 금지한다. 결정2(screen-first-class-node)를 증분으로 반복 적용해 단일 그래프에 점진 수렴한다 — 한 번에 데이터 모델을 갈아엎지 않는다.
